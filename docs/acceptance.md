# 实现与验收状态

更新日期：2026-10-25。

## T1：接口、数据模型和配置

已完成：`docs/artc-architecture.md` 定义了认证、场景、机器人、业务会话、媒体状态、
监听、接管租约、WebSocket、Token、错误和数据库迁移规则。

## T2：业务后端

已完成：FastAPI + SQLite 后端、管理员/客服登录、机器人设备认证、场景隔离、
机器人审批与停用、心跳、在线状态、业务会话、目录、ARTC Token、一次性 WS 票据、
审计和后台过期清理。

## T3：并发人工接管

已完成：SQLite `BEGIN IMMEDIATE` 写事务、部分唯一索引、申请/续租/释放/过期、
客服 WS 断线释放、停用客服释放、客服麦克风发布状态和事件广播。自动化测试验证
10 个并发请求只有 1 个成功。

## T4：Linux 机器人

已完成：后端登录、设备凭证、心跳、机器人 WebSocket、自动建立业务会话、短期 ARTC
Token、`h5mode=True`、媒体入会/离会、接管时暂停自动业务语音、默认机器人麦克风和
客服 PCM 播放。

真实业务链路已通过合成音验证。真实麦克风/扬声器听感仍需设备验收。

## T5：Web 客服工作台

已完成为浏览器 ARTC Web SDK 客服路径：

- `agent/` 启动独立静态 Web 服务并托管页面、ARTC Web SDK 和运行时配置。
- `server/` 不托管客服页面，只提供 REST/WebSocket 控制面。
- 客服 Web 来源通过 `cors_origins` 明确授权跨源访问控制端。
- 官方 ARTC Web SDK 7.3.4 随仓库固定，自动化测试校验 SHA-256。
- 登录、业务状态会话选择、独占认领、机器人音频、可选视频、人工接管、续租、
  释放和离会状态已实现。
- 客服麦克风和摄像头在入会前关闭；只有有效接管租约才允许发布麦克风。
- Windows ARTC SDK 助手使用接管专属 `talk-token` 和独立 `userId` 发布变声客服
  麦克风；助手不订阅远端音视频。
- 客服端提供两个独立音量控制：本机机器人监听音量，以及通过控制面下发到机器人的
  客服播放音量。
- 自定义组合音色支持在线调整基础音色、音调、混响、美声和低/中/高频。
- 本地音频控制仅接受 localhost、同源请求和随机本地控制密钥。
- 浏览器每 5 秒发送助手心跳；30 秒超时、释放接管、控制断开和页面关闭都会停止发布。
- 访问 Token 和 ARTC Token 只保存在页面内存，Token 到期前请求刷新。
- 控制面断开时立即关闭本地麦克风发布；后端按既有 WebSocket 清理规则释放租约。

原 Linux Python 客服端和对应终端联调工具已按确认删除。历史上 Linux 双端合成音频
验证通过，但不能替代当前 Linux 机器人 + Web 客服 + Windows 变声助手的跨 SDK 验收。

当前未完成：

- Linux 机器人与浏览器客服的真实 ARTC 音频闭环。
- Windows 物理麦克风、阿里云变声听感、机器人扬声器和可选摄像头验收。
- Web SDK Token 刷新、断线重连和长时间运行验收。
